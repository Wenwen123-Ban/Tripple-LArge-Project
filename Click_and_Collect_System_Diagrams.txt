Checks performed:

  ✓ Already reserved by this student? (Check existing transactions)
  ✓ Calculate nearest_pickup_day from admin rules
  ✓ Calculate expected_return_date based on loan period


STEP 4: DATABASE UPDATES
━━━━━━━━━━━━━━━━━━━━━━━
Four operations execute:

Operation 1:
  INSERT INTO transactions 
  (book_id, student_id, action, reserved_at, pickup_at, due_at, deleted_at)
  VALUES (123, STU001, 'reserved', NOW(), '2026-05-21', '2026-06-04', NULL)
  
Operation 2:
  UPDATE books 
  SET availability_hint='Reserved', 
      reserve_count = reserve_count + 1 
  WHERE book_id=123
  
Operation 3:
  Calculate queue_position: 
  SELECT COUNT(*) FROM transactions 
  WHERE book_id=123 AND action='reserved' AND deleted_at IS NULL

Operation 4:
  Store transaction ID for response

STEP 7: ADMIN ACTION
━━━━━━━━━━━━━━━━━━
Two possible outcomes:

OUTCOME A: ADMIN CLICKS APPROVE (Green Button)

  - UPDATE books SET availability_hint='Borrowed'

OUTCOME B: ADMIN CLICKS REJECT (Red Button)
  POST /api/transactions/cancel
  Payload: {book_id: 123, student_id: STU001}
  
  Backend updates:
  - UPDATE transactions SET action='cancelled', cancelled_at=NOW()
  - UPDATE books SET availability_hint='Available'
  - Remove from "Pending Reservations" list
  - Status changes to [CANCELLED]
  - Book goes back to Available

TECHNICAL SPECIFICATIONS
================================================================================

Transaction Lifecycle States:
  1. reserved      - Waiting for admin approval
  2. borrowed      - Approved, ready for or in pickup
  3. returned      - Successfully returned by student
  4. cancelled     - Admin rejected or student cancelled
  5. overdue       - Returned after due date

Queue Position System:
  - Calculated as: SELECT COUNT(*) FROM transactions
                   WHERE book_id=X AND action='reserved'
  - Shows student's position in reservation line
  - Helps manage multiple reservations per book

Date Calculations:
  - nearest_pickup_day: Admin configurable rule (default next day)
  - expected_return_date: based on loan_period (default 15 days)
  - due_at: Set when borrowed
  - late if returned after due_at

Notification Channels:
  - SMS: Semaphore API (http://semaphore.co/)
  - Email: (Optional, system ready)
  - In-app: notifications table + browser popup
  - Dashboard: Auto-refresh every 30 seconds

Admin Permissions:
  - View all pending reservations
  - View all active borrows
  - Approve reservations
  - Reject reservations
  - Force return books
  - View reports and analytics
