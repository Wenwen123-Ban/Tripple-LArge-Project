# 11 — Security Analysis

## 11.1 Authentication

- ✅ [VERIFIED FROM: src/api/auth.py:1950-2126] Login is session-based: after bcrypt verification, `session['auth_token']`, role-specific account IDs, `account_type`, `user_role`, and `user_id` are assigned.
- ✅ [VERIFIED FROM: src/api/auth.py:2186-2191] Logout writes a security event and clears the Flask session.
- ✅ [VERIFIED FROM: src/api/auth.py:1959-1986] Account type is differentiated by querying `admins` first and then `students`.

## 11.2 Password Security

| Item | Finding |
|---|---|
| Hashing algorithm | bcrypt via `bcrypt.hashpw(..., bcrypt.gensalt())`. ✅ [VERIFIED FROM: src/core/security.py:4-6] |
| Verification | bcrypt `checkpw`; invalid legacy hashes return False. ✅ [VERIFIED FROM: src/core/security.py:8-16] |
| Salt | bcrypt salts are generated by `bcrypt.gensalt()`. ✅ [VERIFIED FROM: src/core/security.py:4-6] |
| Pepper | ⚠️ [INFERRED] No password pepper environment variable or pepper concatenation was found in `src/core/security.py`. |

## 11.3 Authorization

- ✅ [VERIFIED FROM: app.py:238-267] Central middleware rejects role-scoped APIs when session role does not match.
- ✅ [VERIFIED FROM: src/api/admin.py:23-82] `admin_session_required` decorator enforces `admin_id`, `account_type='admin'`, and `user_role='admin'`.
- ⚠️ [INFERRED] Some endpoints are registered multiple times through blueprints and direct `add_url_rule`, which increases audit complexity.

## 11.4 Input Validation

- ✅ [VERIFIED FROM: src/api/auth.py:707-751] Registration validates ID format, LBC format, contact number, Gmail domain, password length, address length, course/year logic.
- ✅ [VERIFIED FROM: scripts/main/sign_in.js:18-38] Frontend sign-in enforces `YYYY-NNNNN` formatting before submission.
- ✅ [VERIFIED FROM: src/api/books.py:292-310] Bulk import validates column order and required Book No/Title headers.
- ✅ [VERIFIED FROM: src/api/books.py:187-207 and other SQL calls] SQL parameters use `%s` placeholders for values; ⚠️ [INFERRED] dynamic `ORDER BY` and field lists are constrained by hardcoded maps/lists.

## 11.5 Security Headers

✅ [VERIFIED FROM: app.py:374-380] Responses set `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Cache-Control: no-store`.

## 11.6 Rate Limiting

- ✅ [VERIFIED FROM: app.py:104-153] In-memory per-IP rate windows limit login, admin, and student API/page groups.
- ✅ [VERIFIED FROM: src/core/rate_limit_service.py] Login also uses database-backed `ip_token_buckets` consumed by `login()`.

## 11.7 Email Security

- ✅ [VERIFIED FROM: app.py:15-16; src/settings.py:3-18] SMTP settings are read from environment defaults and an external dotenv path.
- ✅ [VERIFIED FROM: src/api/auth.py:23-24] Email confirmation TTL is 15 minutes and resend cooldown is 60 seconds.
- ✅ [VERIFIED FROM: src/api/auth.py:71-105] Token cooldown is enforced before generating a new confirmation token.
